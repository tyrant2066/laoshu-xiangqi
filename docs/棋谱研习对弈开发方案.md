## 1. 需求理解与设计原则

### 1.1 模式本质

「棋谱对弈」不是自由对弈,而是**引导式研习**:用户必须沿着内置棋谱的路线走,对手步由程序自动演示。核心体验三要素:

1. **看得到**——建议步在棋盘上柔和高亮,每一步都有通俗战术讲解(文字 + 语音);
2. **走不偏**——用户点错/走错立即柔和拦截并给出建议着法名;
3. **听得懂**——每步讲解自动朗读,随时可点「🔊 听讲解」重播。

### 1.2 对需求建议的采纳与优化

**采纳**(与需求完全一致):
- book.js 独立解耦、`window.CHESS_BOOKS` 全局挂载、标准化字段(id/title/description/userSide/steps 含 from/to/name/mover/comment)
- 设置弹窗新增模式项;选谱列表 1~10;「🔊 听讲解」重播
- 600ms 自动应手;防走偏拦截文案「请按棋谱路线走哦(建议:xx)」
- Web Speech API + try-catch 静默兜底;不动 api/move.js;UTF-8 纪律

**自行设计的优化点**(在需求之上,理由如下):
1. **数据校验层(loadBooksValidator)**:棋谱是人写的数据,坐标/步序手滑就会造成死局。boot 时用现有 `XQEngine.legalMoves` 从初始局面逐着回放校验,非法谱直接从列表剔除(仅 console.error,不影响任何模式)。这是"数据即代码"的防线,比单纯结构校验更本质。
2. **讲解区独立于状态栏**:状态栏语义是"当前轮到谁",讲解语义是"这一步为什么这样走",两者混用会互相覆盖(讲解长句会挤掉回合信息)。独立 `#bookNote` 条各司其职。
3. **语音开关**:设置弹窗加「语音讲解 开/关」(默认开)。电纸屏用户可能不需要每次朗读,且部分环境 TTS 声音难听,给用户控制权而不是强制。
4. **TTS 播报防堆积**:每次朗读前先 `speechSynthesis.cancel()` 再 speak;自动步讲解与手动重播统一走同一入口,不会出现连读叠音。
5. **悔棋语义**:book 模式悔棋回退到**上一个"轮到用户走"的状态**(退 1~2 步),并重放该步讲解,保证研习连贯。
6. **对手自动应防竞态**:自动落子用独立 token + setTimeout,换谱/切模式/刷新/新局/退出时统一 clearTimeout,杜绝"幽灵落子"(AI 模式已用同一手法,此处复用模式)。

## 2. 数据层设计 js/book.js

### 2.1 挂载方式

```js
/* 老叔之家象棋 内置棋谱数据(纯静态,零依赖) */
(function (g) {
  'use strict';
  g.CHESS_BOOKS = [ ...10 谱... ];
})(typeof window !== 'undefined' ? window : globalThis);
```

- IIFE + 严格模式,不污染其他全局;加载顺序在 ai.js 之后(运行时校验需要 XQEngine,book.js 自身只声明数据)。
- UTF-8 无 BOM 保存(经 Write 工具写入,严禁 PowerShell 读写中文文件)。

### 2.4 数据校验器(boot 时执行)

```
校验步骤:
1. 结构校验: id 唯一、title/description 非空、userSide ∈ {red,black}、steps 非空数组
2. 坐标校验: from/to ∈ [0,89], from !== to, 棋子归属 == mover
3. 规则校验: 从初始局面按 steps 逐着回放, 每着必须 ∈ XQEngine.legalMoves(当前局面, mover)
4. 结果: 校验失败的棋谱从 CHESS_BOOKS 过滤(带 console.error 输出谱名与原因),
        绝不阻止页面启动, 绝不进入其他模式
```

校验器放 ui.js(运行时),book.js 保持纯数据——数据与逻辑职责分离。

## 3. 前端状态机与交互流转(ui.js)

### 3.1 模式接入点

- `freshGame()` 不变;新增 `freshBookGame(book)`:
  - `game = freshGame()` 后覆写 `mode:'book', bookIdx, stepIdx:0`
  - 用户按谱走执 `userSide`,对手步自动演示
- game 对象新增字段:`bookIdx`(当前谱下标)、`stepIdx`(当前应走步下标,0 起)
- 存档 `save()`:结构升 v2,新增 `mode:'book'` 时存 `bookIdx/stepIdx`;`loadGame()` 对 v1 老存档完全兼容(缺字段回退 ai 模式),book 存档恢复时从初始局面重放 steps[0..stepIdx) 重建棋盘(与现有 loadGame 重放 history 同思路)

### 3.2 状态机(核心流转)

```
[book 模式启动]  freshBookGame(book) → stepIdx=0 → 轮到 userSide
        │
        ▼
┌─ 轮到用户(step = steps[stepIdx], 必为 userSide 的着)────────────┐
│   棋盘高亮 step.from/step.to → 状态栏"轮到你走棋"                 │
│   用户点棋子: 非 step.from → 拦截提示"请按棋谱路线走哦(建议:xx)"   │
│   用户点落点: 非 step.to   → 拦截提示(同上), 不改变盘面            │
│   正确落子   → applyMove → stepIdx++ → 显示并朗读该步 comment     │
└──────────────────────────────────────────────────────────────┘
        │ (若 stepIdx < steps.length)
        ▼
┌─ 轮到对手(step = steps[stepIdx], 必为对手方着)─────────────────┐
│   状态栏"自动演示中…" → 600ms 后 applyMove → stepIdx++          │
│   显示并朗读该步 comment                                        │
└──────────────────────────────────────────────────────────────┘
        │ (循环回到"轮到用户", 直到)
        ▼
[谱完]  statusText('棋谱研习完成!') + toast('恭喜,本局研习完成')
        🔊 听讲解 仍可重播最后一步
```

- 讲解游标:完成第 n 步(用户或对手)后,`#bookNote` 显示 `第n步 · 着法名 —— comment`,同时 speak(comment)。
- 用户走对一步后,**若下一步是用户步则立即高亮下一步**(连续训练);若下一步是对手步则启动 600ms 定时器。

### 3.3 防走偏拦截(tapSquare 前置分支)

在现有 `tapSquare(sq)` 内、通用逻辑之前插入 book 分支:

```js
if (game.mode === 'book') {
  var st = CHESS_BOOKS[game.bookIdx].steps[game.stepIdx];
  if (!st) { /* 谱已完 */ return; }
  if (game.turn !== userSide) return;              // 对手自动演示中, 忽略点击
  if (sel < 0) {
    if (sq === st.from) { sel = sq; redrawAll(); }  // 只允许选中建议棋子
    else toast('请按棋谱路线走哦(建议:' + st.name + ')');
    return;
  }
  if (sq === st.to && legalMoves 含 (sel→sq)) { doHumanMove(sel, sq); }
  else { sel = -1; redrawAll(); toast('请按棋谱路线走哦(建议:' + st.name + ')'); }
  return;
}
```

- 关键点:sel 只接受 `st.from`;落点只接受 `st.to`(且必须合法,双保险);
- 走错后 toast 自动恢复(现有 toast 机制,2.5s),不改变盘面;
- 谱完状态:`game.over` 置真语义不同——book 模式用 `stepIdx >= steps.length` 判定完成,不触发将死/困毙结果(谱内不含残局)。

### 3.4 对手自动应(600ms 防竞态)

```js
var bookTimer = 0;  // ui.js 顶层
function scheduleBookMove() {
  if (bookTimer) clearTimeout(bookTimer);
  var st = ...; if (!st || st.mover === userSide) return;
  bookTimer = setTimeout(function () {
    bookTimer = 0;
    if (!game || game.mode !== 'book') return;   // 竞态防线
    applyMove(game, st.from, st.to);
    stepIdx++; ... 显示+朗读 comment; 若还有用户步则 updateStatus() 等待
  }, 600);
}
```

- 所有会离开 book 模式的操作(换谱/切模式/新局/刷新/悔棋/退出)统一先 `clearTimeout(bookTimer)`,与 AI 模式 aiToken 同样的纪律;
- 悔棋:回退至"上一个轮到用户的状态"(退 1~2 步),`stepIdx` 同步回退,重放该步讲解。

### 3.5 各操作在 book 模式的行为

| 操作 | 行为 |
|---|---|
| 开始(新局) | 重开当前谱(bookIdx 不变,stepIdx=0,清 history) |
| 悔棋 | 回退到上一个轮到用户的状态(1~2 步),重播讲解 |
| 刷新(去残影) | 不变(重绘),同时清掉待演示定时器?——否,保留当前进度只重绘 |
| 设置-切模式 | 退出 book(清定时器),保持其他模式既有行为 |
| 设置-换谱 | 立即 freshBookGame(新谱),清定时器 |
| 语音开关 | 仅影响 TTS,不动进度 |

## 5. TTS 语音讲解设计

### 5.1 speak(text) 实现要点

```js
function speak(text) {
  try {
    if (!text) return;
    if (typeof window === 'undefined' || !('speechSynthesis' in window)) return; // 能力检测
    var u = new SpeechSynthesisUtterance(String(text));
    u.lang = 'zh-CN';
    u.rate = 0.9; u.pitch = 1;
    // 先取消队列, 防连读堆积
    try { window.speechSynthesis.cancel(); } catch (e) {}
    window.speechSynthesis.speak(u);
  } catch (e) { /* 任何环境异常都静默忽略, 绝不抛出 */ }
}
```

- 朗读文本 = `第n步,着法名。comment`(如"第3步,马二进三。出马保护中兵,同时准备出车。");
- 语音开关关闭时直接 return;
- 调用点统一:`showComment(step, idx)` 函数(更新 #bookNote + speak),自动步/用户步/听讲解重播全部走它,单一入口保证行为一致。

### 5.2 降级矩阵

| 环境 | 表现 |
|---|---|
| 支持 speechSynthesis(现代浏览器/EinkBro) | 朗读 + 文字 |
| 不支持(极简 WebView/Via 老内核) | try-catch 静默,仅文字,零异常 |
| 支持但无声(设备静音/无语音包) | speak 调用不报错,文字正常 |
| 用户关闭语音开关 | 仅文字 |

### 5.3 播放时机与打断

- 用户步完成 → 立即朗读该步;对手步 600ms 落子后朗读;
- 连续快走(用户快速连对两步)→ cancel 先取消上一步,只读最新;
- 「🔊 听讲解」→ 重播当前步;
- 悔棋回退 → 重播回退后的当前步。

## 6. 持久化与恢复

- `save()`:`{ v: 2, mode, level, playerSide, ..., bookIdx, stepIdx, speakOn }`
- `loadGame()`:
  - v1 存档(无 v2 字段):完全按现有逻辑,book 字段缺失自动忽略 → 回退 ai 模式;
  - book 存档:校验 bookIdx 在合法范围(0~9)且 stepIdx ≤ steps.length,越界回退 ai 模式;
  - 恢复方式:初始局面重放 steps[0..stepIdx) 重建棋盘与 history(与现有 history 重放同思路,棋盘一致性校验沿用);
- 语音开关独立字段持久化。
